# Global Rule: Swarm Quality Doctrine (Measured Anti-Patterns)

These directives encode Anthropic's officially published, measured findings about multi-agent systems. They bind `domain-architect` (design time), `persona-engineer` (write time), and `prompt-evaluator`/`qa-validator` (evaluation time) for every generated swarm.

**Directives:**

1. **Single-Agent Justification (burden of proof on decomposition):** Multi-agent systems cost 3–15x the tokens of an equivalent single agent, and "a well-designed single agent with appropriate tools can accomplish far more than many developers expect" (Anthropic). Every blueprint MUST state in `single_agent_justification` why one well-tooled agent cannot do the job — the only valid grounds are context pollution, genuinely parallel independent workstreams, or a specialization threshold. Evaluators reject blueprints without it.

2. **Context-Boundary Decomposition, Not Phase Decomposition:** Splitting one body of work into sequential pipeline stages ("planner → implementer → tester → reviewer") is an official Anthropic anti-pattern — each handoff loses context ("telephone game"). Group tasks that share necessary context into ONE agent: the agent implementing a feature also writes its tests. GOOD boundaries: independent research paths, components with defined APIs, blackbox verification of finished output. BAD boundaries: sequential phases of the same work, tightly coupled components, anything needing constant state sync. `prompt-evaluator` flags phase-chain rosters as a category error routed back to `domain-architect`.

3. **Prompt Length Budget (measured):** A `CLAUDE.md` beyond ~200 lines measurably REDUCES instruction adherence — important rules get lost in noise. Generated orchestrator prompts must be dense but bounded: every section complete, no filler, and content that isn't orchestration-critical modularized into `.claude/rules/` (path-scoped via `paths:` where applicable). `qa-validator` flags any generated `CLAUDE.md` exceeding ~200 lines. Depth of thought, not length of file, is the quality bar — the same discipline applies to agent bodies: rich in operational detail, zero boilerplate padding.

4. **Verifier Hardening ("early victory" countermeasure):** Verification agents are documented to produce false positives — declaring work done without thorough testing. Every generated verifier/reviewer/QA persona MUST carry explicit completeness language: "you MUST run the complete test suite", "you MUST test edge cases" — never a vague "verify this works". A generator agent NEVER approves its own output; verification always runs in a fresh-context agent. Fresh-context reviewers flag only correctness and requirement gaps, NOT style preferences — an evaluator told to find gaps will always find something, and nit-chasing causes over-engineering.

5. **Manifesto Verbatim, Artifacts Just-in-Time:** The user's original request and vision pass down VERBATIM (Visionary Context Passing — never compressed). Research artifacts, file contents, and large reference material are the opposite: pass lightweight identifiers (paths, queries, report filenames) and let each agent load what it needs at runtime via its tools — do not pre-dump bulk content into every delegation prompt.

6. **Tool Design Standards (for `tool-smith` and `mcp-integrator`):** Consolidate related operations into fewer, higher-level tools rather than many narrow API-mirroring ones — if a human engineer can't tell which of two tools to use, neither can an agent. Use consistent prefix namespacing for related tools. Custom tools return semantically meaningful identifiers (not opaque UUIDs), support concise/detailed response formats where output can be large, and emit actionable error messages that let the calling agent self-correct.
